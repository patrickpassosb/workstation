Workstation Security Lab — Plan

Branch prebuilt-only · Status: review complete · Mode: build-ready draft

Harden first Expand after Manual MCP Multi-use threat model

Focus choice. Harden the existing lab before adding new tools. The current lab covers static analysis (Semgrep, CodeQL) plus two Docker-isolated scanners (Nuclei, AFL++) and two manual proxies (Caido, Burp). The biggest security wins are wrapper hardening, missing secret/SCA/IaC coverage, and a clearer MCP-audit story — all cheaper than adding new repos.

1. Scope & threat model

The lab serves three overlapping use cases:

  1. Personal appsec work on the user's own codebases.
  2. Authorized third-party testing (bug bounty, pentest engagements).
  3. Learning / CTF (HackTheBox, portswigger labs, etc.).

Design implications:

  • Default to the strictest (third-party) case: isolation, audit trail, no silent credential registration, no host-level side effects from scanning tools.
  • Allow the user to opt into a relaxed mode for personal/CTF work via a single env var (e.g. LAB_RELAXED=1) that loosens the wrappers.
  • Treat every tools/*.sh script as audited at install time — no post-install hooks that phone home, no telemetry without explicit opt-in.

2. Decisions

3. Phase 1 — Hardening (no new tools)

3.1 Wrapper isolation rewrite

Replace the inline install_user_executable blocks in tools/nuclei.sh and tools/aflpp.sh with shared helpers in lib/helpers.sh:

  • install_docker_wrapper <name> <image> <mount_path> [env…]
  • install_uvx_wrapper <name> <pkg> [warn_message]

Wrapper behavior:

exec docker run --rm \
  --read-only \
  --cap-drop=ALL \
  --security-opt=no-new-privileges \
  -u "$(id -u):$(id -g)" \
  -v "$PWD:<mount>:rw" \
  -w <mount> \
  --network=lab-none \
  "$image" "$@"

Add --network=host escape hatch via LAB_RELAXED=1 nuclei-docker … (printed in --help output).

Create a dedicated lab-none network in tools/security-lab.sh (idempotent, docker network create --internal lab-none 2>/dev/null || true).

3.2 Verify-block correctness

The current Security Lab Verification block in setup.sh uses is_installed, which only checks command -v. This fails for tools installed to ~/.local/bin when the parent shell has not yet sourced the new PATH.

Replace the verify block with explicit checks:

  • For each tool, check the actual artifact:
    • test -x ~/.local/bin/obsidian-app || test -x ~/AppImage/Obsidian-*.AppImage
    • test -x ~/.local/bin/codeql and test -x ~/.local/codeql/codeql
    • test -x ~/.local/bin/nuclei-docker
    • etc.
  • Fall back to command -v for tools that are always on PATH (e.g. semgrep, ghidraRun).

3.3 CodeQL portability

Current tools/codeql.sh hard-fails on non-x86_64. Replace with:

case "$(uname -m)" in
  x86_64) asset="codeql-bundle-linux64.tar.gz" ;;
  aarch64) asset="codeql-bundle-linux64.tar.gz" ;;  # CodeQL ships a single Linux x64 bundle; arm users get a clear warn
  *) warn "CodeQL bundle is x86_64-only on Linux; skipping"; exit 0 ;;
esac

And keep the existing flow for x86_64. On aarch64, print a clear warn and exit 0 so it does not break the rest of setup.

3.4 Snyk auth callout

In tools/snyk-agent-scan.sh, add a post-install log line:

log "Set SNYK_TOKEN before use: export SNYK_TOKEN=..."
log "Or run: snyk-agent-scan-safe auth"

And reference it in docs/security-lab.md.

3.5 MCP one-shot consent prompt

Add configs/lab-mcp-consent.sh:

  • Print the table of MCPs (name, repo URL, what it can do) — pulled from a small JSON/YAML in configs/lab-mcps.json.
  • For each, default to skip; only register if the user explicitly says y.
  • If any are approved, print the exact codex mcp add … / claude mcp add … commands for the user to run themselves (do not auto-run; the parent process may not have the agent CLI in PATH).
  • Wire into setup.sh after the security-lab install block.

3.6 Ghidra launcher search hardening

The current find … | sort -V | tail -n 1 in tools/ghidra.sh can pick a stale binary. Tighten to:

find "$HOME/.local" -maxdepth 4 -name ghidraRun -type f -newer /etc/hostname 2>/dev/null | head -n 1

Or, better, accept GHIDRA_HOME env var and short-circuit to that.

3.7 ~/hacking/AGENTS.md

Create a tiny policy file in the lab root that any agent reading the workspace will see:

# Security Lab — Agent Policy

- This workspace is for **authorized** testing only.
- Do not run any tool that executes code or exfiltrates data
  without explicit user confirmation in the current session.
- Do not register MCP servers. Suggest the command; let the user run it.
- Do not modify Burp / Caido extensions, tokens, or licenses.
- All findings belong in `~/hacking/findings/`. Do not write to `$HOME`.

Generate it from tools/security-lab.sh.

4. Phase 2 — Coverage gaps

4.1 Secret scanning

Add tools/gitleaks.sh (host install via GitHub release binary, github_release_install). No wrapper needed; it is a passive scanner.

Add a tools/pre-commit.sh that installs pre-commit via uv tool install and writes ~/.config/pre-commit/repo-templates/security.yaml with gitleaks + shellcheck + ruff (Python) hooks. The user copies it into their projects.

4.2 SCA / SBOM

Add tools/trivy.sh. Trivy is small, covers filesystem + image + IaC, and avoids Snyk's auth footprint for casual use.

4.3 IaC scanning

Trivy covers Terraform / K8s manifests. No separate tool needed.

4.4 Recon / OSINT

Out of scope for the auto-install path. Add a docs/recon.md pointer list (amass, subfinder, httpx) so the user knows what to add when they need it, with one-line install commands.

4.5 Snyk vs Trivy default

Document the trade-off: Trivy is preferred for personal/CI use (no auth, broader coverage); Snyk agent-scan stays for app-via-MCP workflows.

7. Verification plan

For each phase, run on a fresh Fedora KDE VM and a fresh Ubuntu 24.04 VM (the only two supported targets):

  1. Wrapper isolation 
    LAB_RELAXED=0 nuclei-docker -h      # uses lab-none, no host network
LAB_RELAXED=1 nuclei-docker -h      # uses host network, prints warning
docker run --rm --network=lab-none alpine ping -c1 1.1.1.1  # must fail
  2. Verify block — pre-source ~/.local/bin and re-run setup; every lab tool should print ✓.
  3. MCP consent — run setup with no stdin, confirm it skips registration cleanly.
  4. Gitleaks/Trivy — clone a small repo with a known dummy secret and confirm detection.
  5. Pre-commit — pre-commit run --all-files in a project that copies security.yaml.

8. Risks & rollback

  • Wrapper breakage. Some scanners (e.g. nuclei templates, afl++ LLVM plugins) genuinely need network or write access. The LAB_RELAXED=1 opt-in covers this; document it in the quickstart.
  • Trivy false positives. Add a short note in the quickstart about .trivyignore.
  • Pre-commit friction. Some repos disable hooks. Document how to bypass with git commit --no-verify for the rare case.
  • Rollback. Each new file is additive. Wrappers are replaced in place, but the new helpers export LAB_RELAXED=1 as a no-op fallback, so a partial re-install still works.
